## 2. TRADING PLATFORM QUALITY STANDARDS

**These are non-negotiable for ALL code contributions:**

### Type Safety (Mandatory)
```python
# ❌ WRONG - No type hints
def get_signals(symbol):
    return {"signal": "buy"}

# ✅ CORRECT - Full type safety
from typing import Dict, Optional, List
def get_signals(symbol: str) -> Dict[str, Any]:
    """Get trading signals for a symbol.
    
    Args:
        symbol: Stock ticker (e.g., 'SPY', 'AAPL')
    
    Returns:
        Dictionary with signal metadata and confidence scores
    """
    return {"signal": "buy", "confidence": 0.95}
```

### Error Handling (Mandatory)
```python
# For API endpoints
try:
    result = process_signal(request.symbol)
    return result
except ValueError as e:
    raise HTTPException(status_code=400, detail=f"Invalid input: {str(e)}")
except Exception as e:
    raise HTTPException(status_code=500, detail=f"Server error: {str(e)}")
```

### FastAPI Integration (Mandatory)
- All endpoints must have Pydantic models
- CORS middleware configured properly
- Error responses standardized
- API keys read from environment (never hardcoded)

### Financial Accuracy (Mandatory)
- Always include data source attribution
- Validate decimal precision for prices/volumes
- Include timestamps in all analyses
- Handle market-hours vs after-hours distinctions when relevant

### OpenBB Integration (Mandatory)
- Use `from openbb import obb` for data access
- Properly initialize with API keys from environment
- Cache results when appropriate (avoid rate limits)
- Handle provider fallbacks gracefully

### Documentation (Mandatory)
```python
# Every function needs:
# 1. Docstring with Args, Returns, Raises
# 2. Type hints on all parameters/returns
# 3. Inline comments for complex logic
# 4. Example usage in docstring for public APIs
```
